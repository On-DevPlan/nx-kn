Obsidian 页：四种组织方式

现状是一列纵向堆叠：vault 配置 → 规范文档登记表 → 解析结果 → 知识库迁移 → CLI 提示。 五块卡片权重相同，而「看项目、导包、导入」才是这一页真正要做的事，却被压到第三张卡之后； 配置类内容（vault / 登记表）与操作类内容混在一起。四个方向都在解决同一件事——把主任务提上来，把设置沉下去，区别在组织手段。

A

工作台（主从双栏）

结构改动最大
  • 左边项目列表，右边「详情 + 导出/导入并排」——选中谁就操作谁，不用滚
  • vault 体检压成一条状态条；设置与登记表收进 <details>
  • 结果用 包 / 大小 / 落点 / 下一步 的结构化行，不是一坨 pre
代价：两栏在 1280 以下会挤；项目多时左栏要滚动，需要接受「列表可能比视野长」。

B

向导（三步走）

交互改动最大
  • 导出 / 导入是两个模式，各自 3 步：选项目 → 选去处 → 结果
  • 一屏只有一个主按钮，危险操作（覆盖）放在预演之后才出现
  • 最能把「先预演、再落地」这条纪律讲清楚
代价：高频重复操作变慢（每次导出都要走三步）；老手会嫌它啰嗦。
打开原型 B →
C

总览（表格 + 抽屉）· 已选定

已出 v2 优化版
  • v2 已去掉 KPI 大卡：信号只报「要动手的」（未解析 / 缺根文档），健康态一行灰字
  • 表格可排序 + 筛选 chip；项目名下带代码库绑定路径，迁移时不用点开确认
  • 导入按钮在预演前禁用，「覆盖」只在预演报出冲突后才能勾——危险操作后置
代价：抽屉多一层，单项目时反而比 A 多一次点击；表格在窄屏要横向滚。

D

渐进重排（保留现有视觉）

改动最小
  • 卡片的观感、圆角、行高全不动，只重排层级与列宽
  • 「项目 + 迁移」合成一张卡：导出/导入并排，结果固定在卡底
  • 设置、登记表、CLI 提示全部折叠到页面下方
代价：上限也最小——仍是单列一页，项目变多时只能往下长。

共同保留的产品约束：只有 --bad 一个语义色（健康态走墨色 / 灰，不引入绿色）、 28px 行高与 14px 卡片圆角、结果不靠 toast 承载、 「未读到 ≠ 没有」（首帧显示 … 而不是 0）。四个原型的项目数据都是示意值。
