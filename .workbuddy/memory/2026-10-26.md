## 知识库迁移：obsidian export / import（zip）

需求：支持导出一个或多个项目为 zip，且能导回 kn，做知识库迁移。

**为什么自己写 zip（`src/core/zip.js`，新增约 300 行，零依赖）**
- 依赖表只有 5 个必需包，这里只需要「打包一批 md」这一个子集；
- 导入是安全敏感路径：zip-slip、单文件 64MB / 总量 512MB 上限、逐条 CRC 必须自己控，
  不能指望库「信任压缩包」的默认行为；
- 只支持 store(0) / deflate(8)；ZIP64、加密、分卷、未知压缩方法一律报错，不静默读错。
- 写侧逐条选方法（deflate 没变小就用 store）；文件名置 UTF-8 标志（bit 11）中文不乱码；
  时间用 DOS 格式（2 秒精度），导入时 `utimes` 还原——否则 `projects` 的「最近更新」会全跳到今天。

**包格式**：`manifest.json` + `projects/<名>/…`。manifest 记 format/version/createdAt/app、
每个项目的 name/dir/projectPath/fileCount/files[{path,size,sha256}]。
**不含 `.zvec-grep` 索引**：它绑死绝对路径与 embedding 维度，带过去只会让检索静默返回旧结果。

**导出** `obsidian export --name a,b --out <zip>` / `--all`（两者互斥）。`--out` 必填，
相对路径按**当前工作目录**解析（不是 vault）。名字走 `assertSafeName` 且必须已存在。
踩坑：flag 声明成 `names` 时 CLI 只认 `--names`，演练才发现 → 改成 `name`（与 `--spec` 的单数+逗号一致）。

**导入** `obsidian import --file <zip> [--force] [--dry-run] [--project-path]`
- 以 manifest 为准逐文件校验 sha256；包内多余条目进 `ignored`，不落盘。
- 同名默认**整体拒绝**（不做部分导入），`--force` 才覆盖；覆盖前把旧目录整份备份到
  `dataDirFromEnv()/backup/import-<ts>/`（跟 store 走 → 测试天然隔离）；覆盖 = **替换**（先 rm 再写），
  否则会留下上游已删的陈旧笔记（那种文件让红链「看起来解析成功」，最难发现）。
- `project:` 默认原样保留，`projectPathExists` 如实标出；`--project-path` 只改 Base 那一行，
  且目标目录必须存在。改行用索引拼接——`String.replace(fmBody)` 在正文出现相同串时会改错位置。
- 校验先全跑完再动盘：缺文件 / 哈希不符 / 路径非法 → 一个文件都不写。
- `--dry-run` **不能被冲突拦住**（首版单测就挂在这：预演的意义就是先看见冲突）。

## 16:25–16:45 导出「默认下载」+ 导入「拖拽上传」

用户两点需求：导出不填路径 = 走浏览器下载；导入支持文件拖拽。两者本质都是
「浏览器与终端能力不对等」：浏览器给不出本地路径、也没有「写到哪」的概念。

**运行时新增两个显式能力开关**（src/runtime/api.js，由 action 声明，不靠 content-type 猜）：
- `httpFile: true`：run 返回 `{ download: { buffer, filename } }` 时直接写字节流
  （Content-Disposition 用 `filename=` ASCII 兜底 + `filename*=UTF-8''` 真名——
  项目名是中文，只写 filename= 会变乱码）。
- `httpUpload: { maxBytes }`：非 JSON content-type 的 POST 视为原始字节，落临时文件 →
  `ctx.file = 临时路径` → run 结束 finally 删。**导入逻辑只有一份（认路径）**，
  上传只是「怎么把字节变成路径」；其余参数走 query string。
- service 侧 `exportProjects` 收 `transport`（`run(ctx, { transport })` 本来就有）：
  最初写成「不给 `--out` 且非 http → badInput」，**已被推翻**（见下条 16:50）。

**包名规则收进服务端**（`kn-<项目|all>-<时间戳>.zip`，非法字符换 _ 截 40 字符），
前端只负责保存——CLI 与面板导出的命名只有一处。

**前端**（client.js 加 `apiDownload` / `apiUpload` / `saveBlob`）：
- 下载必须 POST（要带项目名），拿 blob 再 `a.download` 触发——不能 `<a href>` 直跳，
  否则出错时用户看到一页 JSON。
- 拖拽区是 `<label class="dropzone">` + hidden file input（点选/拖入同一个回调）；
  **每次操作重新上传**：服务端临时文件一次请求就删（不留状态），预演/导入是两次独立请求。
- 隐藏 file input 的 onChange 结尾要 `e.target.value = ''`，否则连选同一文件第二次不触发。

**验证**：`tests/unit/api-transfer.test.mjs` 5 例（下载字节流+content-disposition、
CLI 缺 out 报错、上传预演回显原始文件名、JSON 兼容共存、content-length 超限先拒）；
unit 263/263、lint 0；CDP 实测：空路径导出 → anchor.download =
`kn-sedoc-fe-8.60-20261026-163523.zip`（154439 B）；DataTransfer 拖入 zip → 输入框禁用 +
预演结果显示「包 拖拽测试.zip」（原始文件名）+ 冲突提示。

## 16:50 CLI 导出不给 --out：从「报错」改成「就地落包」

用户报「导出失败」，贴的是 `用法: nx-kn obsidian export … —— 缺少参数 --out`。

**先分清两种可能**：`缺少参数 --out` 只可能来自 `runtime/spec.js` 的 `applySpec`，
即**声明里 `out.required === true`**；当前源码早已改成可选，所以那一份是旧代码
（`where.exe nx-kn` 在本会话 PATH 上查不到任何副本，用户终端 PATH 与宿主不同，
无法直接定位）。但无论如何，**CLI 缺 `--out` 报错这件事本身就该改**：

- 原判据「终端没有下载这回事 → 缺 out 属于笔误 → 报错」是错的。终端里不指定输出路径
  的合理默认就是「就地生成一个包」，报错只是逼人补一遍 `--out` 再敲一次。
- 新行为（`service.js: exportProjects`）：按通道分流，不是按猜——
  `transport === 'http'` 且无 out → 回字节给浏览器；其余（CLI）无 out → 落在 **cwd**，
  名字复用 `exportFilename()`（与面板下载同一套规则 `kn-<项目|all>-<ts>.zip`）。
- 返回值加 `defaultedOut: true`，`render` 追加「未指定 --out，已落在当前目录」——
  「这包写到哪了」必须打出来，否则等于让人去猜。
- **同名不覆盖**：`uniqueOutPath()` 依次试 `-2` / `-3`…。同一秒内导两次会撞名，
  静默盖掉上一个包是不可逆丢数据。
- 单测：`api-transfer.test.mjs` 那条从「rejects --out 必填」改成「chdir 到临时目录 →
  真的写出 zip → 文件名匹配 → 再导一次不覆盖前一个」；`obsidian-migrate.test.mjs`
  里同一条删除（默认落点只在一个地方钉，避免两处断言各自漂移）。

**验证**：lint 0；unit **263/263**；真实 vault 上在临时 cwd 跑
`node bin/kn.mjs obsidian export --name sedoc-fe-8.60` → 29 文件 / 320.4 KB → 包 154438 B，
落在 `kn-sedoc-fe-8.60-20261026-164836.zip` 并打印绝对路径；`help obsidian` 里 `[--out …]` 已在方括号内。
