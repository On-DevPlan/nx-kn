## 修复「更换目录实际没有更换」（用户报告）

**根因**：`useToast()` 返回的就是 toast 函数本身，但 kb 视图写成 `const { toast } = useToast()`

→ store.json 其实写成功了，界面却不刷新，用户看到的就是「更换目录没生效」。**静默失效，不报错不白屏。**

**证据链（CDP 实测，非推断）**：
- patch `window.fetch` 抓包：`POST /api/kb/use` 确实发出、后端 200/404 正常，但 `.toast` 恒为空
- React fiber 检测：input 的 `fiber.ref.current === input` 为 true → **ref 正常**，排除「ref 没挂上」
- 对照组：错误路径（不存在的目录）修复前也无提示，修复后弹「知识库目录不存在: …」

**改动（3 处）**：
1. `src/modules/kb/view.jsx` → `const toast = useToast()`
2. `src/modules/settings/view.jsx` → 同上（**模板自带缺陷**）
3. `src/web/frontend/components/ui.jsx` → `useToast()` 加自引用防呆 `toast.toast = toast`，
   让 `const { toast } = ...` 这种写法不再静默失效

**顺带修（也是「像没生效」的成因）**：
- `pickVault` / `reindex` 改为**乐观更新**：POST 响应已含新目录全部信息，直接落 UI。

**实测数据**：保存后 **400ms 内**目录行已更新、按钮已恢复可用（修复前 3000ms 仍是旧值、4s 才恢复）。

### ① 致命：参数含空格时整条 zg 调用被 cmd.exe 切碎

首次 `index --root "D:\Obsidian Vault"` 直接失败：`zg index accepts at most one root path`。

**根因**：Windows 上 zg 是 `.cmd` 垫片，必须经 `cmd.exe /d /s /c` 调用；而 cmd 会**把命令行
再解析一遍**，Node 的默认 spawn 又会给整行套引号、把内层 `"` 转义成 `\"`（cmd 不认）。
两者叠加 → `"D:\My Vault"` 裂成 `\"D:\My` + `Vault\"` 两个参数。

**影响面远大于路径**：**参数里只要有空格就会坏**，`query "多个 词"` 同样中招——只是此前
所有实测问句/路径都没带空格，所以从没暴露。

**修法**（`core/zg.js`）：自己加外层引号（cmd `/s` 剥掉它）+ `windowsVerbatimArguments: true`。
**A/B 实测**：A（原写法）→ `at most one root path`；B（新写法）→ `Workspace index is not configured`
且根路径回显正确。已加两层回归：smoke 用真 zg 跑带空格路径，单测钉住源码两处写法。

### ② 千分位数字被截断（面板「1 片段」）

`zg status` 输出 `Entities    1,490`，而 `parseStatus` 的数字模式写成 `(\d+)`，**在逗号处停下**
→ 1490 读成 `1`，面板显示「1 片段」（`num()` 里那句 `replace(/,/g,'')` 永远等不到逗号，成了摆设）。
覆盖度 / Queue / Changes 同类修复，补单测。

### ③ 「226 篇」对不上「173 已索引」——zg 有一套自己的默认忽略

账终于算清（226 − 48 − 5 = 173）：

| 少掉的 | 原因 |

| 其余 | 14 个顶层目录 + 根层 15 篇 = 211+15 = 226，全部核对过 |

zg 的默认忽略（源码 `engine/pipeline/indexing/scanner/index.js`）：隐藏目录/文件、
`DEFAULT_IGNORED_DIRECTORY_NAMES`（node_modules/dist/build/out/target/tmp/temp/logs/locale…）、
**嵌套 git 仓库整棵**、空文件，另外**各目录的 `.gitignore` 也会被遵守**。

**修法**：`countNotes` 改为按同口径估算（隐藏目录 + 忽略目录名 + 嵌套 git 仓库 + 空文件），

`files/filesTotal`。smoke 加了一条构造 vault 的回归（四类排除一起钉）。

- 2FA-bypass GAT **已不能**做建/删 token、改包权限/维护者/trusted publishing 配置、管组织成员
  （全部要交互式 2FA）。
- **下一个变更目标 2027 年 1 月**：2FA-bypass GAT **将失去直接 publish**，只剩「读私有包 +
  **staging** publish（由维护者 2FA 批准）」。官方推荐迁移到
  **trusted publishing (OIDC)** 或 **staged publishing**。

**因此两条路**：(a) 给 token 勾上 Bypass 2FA —— 今天能发，但 2027-01 失效；
(b) 先**手动交互发一次**让包存在 → 在 npm 包设置里配 **Trusted Publisher**（repo `On-DevPlan/nx-kn`
+ workflow `npm-publish.yml`）→ 改用 OIDC 发布，**完全去掉 token secret**。
走 (b) 需注意：`actions/setup-node` 的 `registry-url` 会写 `_authToken=${NODE_AUTH_TOKEN}`（空值时可能
干扰 OIDC，要处理）；且 trusted publishing 需要 **npm ≥ 11.5.1**，Node 22 自带的是 10.x，
workflow 里得加一步升级 npm。`permissions: id-token: write` **已在 workflow 里**（本来就是为
`--provenance` 加的），OIDC 可直接复用。

**关键设计决定（都写进注释了）**：
1. **抓取产物 = 普通 .md 目录 + 自动登记为 kb vault** → 索引/检索/增量/多库合并零特化复用。
   跨模块耦合绕开方式：crawl 直接 `mutateStore` 往 `store.kb.vaults` push（不 import kb 模块，
   模块互依禁令不允许）。只推 `{path,name,addedAt}`，`normalizeKb` 会补默认并按 path 去重。
2. **sources 目录跟着 store 走**：`sourcesDir() = dirname(storePathFromEnv())/sources`，
   而不是钉死 `~/.nx-kn`。这样 `NX_KN_STORE`/`--store` 一个开关就同时搬动全部数据 →
   **测试隔离自动覆盖采集产物**（若钉死 APP_DIR，测试会写用户真实 `~/.nx-kn/sources`）。
3. **增量哈希只算正文**，不含 frontmatter（`fetchedAt` 每次都变，算进去增量永远失效）。
4. **`crawl remove` 默认保留**文件+索引+知识库登记；`--purge` 才连目录带 kb 登记一起删
   （与 kb remove「只解登记」语义对齐）。
5. **一处都没抓到 → 抛 EXTERNAL**（绝不建空内容的源）；但目录里已有上次成果时不抛
   （站点临时抽风不该把上次的成果判死）。
6. sitemap 的 `sitemapindex` 递归限深 3 层、限 5000 条；只抓同源；串行 + 300ms 节流
   （`NX_KN_CRAWL_DELAY_MS` 可关，测试用 0）。
