## 修复「更换目录实际没有更换」（用户报告）

**根因**：`useToast()` 返回的就是 toast 函数本身，但 kb 视图写成 `const { toast } = useToast()`

→ store.json 其实写成功了，界面却不刷新，用户看到的就是「更换目录没生效」。**静默失效，不报错不白屏。**

**证据链（CDP 实测，非推断）**：
- patch `window.fetch` 抓包：`POST /api/kb/use` 确实发出、后端 200/404 正常，但 `.toast` 恒为空
- React fiber 检测：input 的 `fiber.ref.current === input` 为 true → **ref 正常**，排除「ref 没挂上」
- 对照组：错误路径（不存在的目录）修复前也无提示，修复后弹「知识库目录不存在: …」

1. `src/modules/kb/view.jsx` → `const toast = useToast()`
2. `src/modules/settings/view.jsx` → 同上（**模板自带缺陷**）
3. `src/web/frontend/components/ui.jsx` → `useToast()` 加自引用防呆 `toast.toast = toast`，

**顺带修（也是「像没生效」的成因）**：

**实测数据**：保存后 **400ms 内**目录行已更新、按钮已恢复可用（修复前 3000ms 仍是旧值、4s 才恢复）。

### ① 致命：参数含空格时整条 zg 调用被 cmd.exe 切碎

首次 `index --root "D:\Obsidian Vault"` 直接失败：`zg index accepts at most one root path`。

**根因**：Windows 上 zg 是 `.cmd` 垫片，必须经 `cmd.exe /d /s /c` 调用；而 cmd 会**把命令行
再解析一遍**，Node 的默认 spawn 又会给整行套引号、把内层 `"` 转义成 `\"`（cmd 不认）。
两者叠加 → `"D:\My Vault"` 裂成 `\"D:\My` + `Vault\"` 两个参数。

**影响面远大于路径**：**参数里只要有空格就会坏**，`query "多个 词"` 同样中招——只是此前
所有实测问句/路径都没带空格，所以从没暴露。

**修法**（`core/zg.js`）：自己加外层引号（cmd `/s` 剥掉它）+ `windowsVerbatimArguments: true`。
**A/B 实测**：A（原写法）→ `at most one root path`；B（新写法）→ `Workspace index is not configured`
且根路径回显正确。已加两层回归：smoke 用真 zg 跑带空格路径，单测钉住源码两处写法。

### ② 千分位数字被截断（面板「1 片段」）

`zg status` 输出 `Entities    1,490`，而 `parseStatus` 的数字模式写成 `(\d+)`，**在逗号处停下**
→ 1490 读成 `1`，面板显示「1 片段」（`num()` 里那句 `replace(/,/g,'')` 永远等不到逗号，成了摆设）。
覆盖度 / Queue / Changes 同类修复，补单测。

### ③ 「226 篇」对不上「173 已索引」——zg 有一套自己的默认忽略

账终于算清（226 − 48 − 5 = 173）：

| 少掉的 | 原因 |

zg 的默认忽略（源码 `engine/pipeline/indexing/scanner/index.js`）：隐藏目录/文件、
`DEFAULT_IGNORED_DIRECTORY_NAMES`（node_modules/dist/build/out/target/tmp/temp/logs/locale…）、

**修法**：`countNotes` 改为按同口径估算（隐藏目录 + 忽略目录名 + 嵌套 git 仓库 + 空文件），

  **trusted publishing (OIDC)** 或 **staged publishing**。

### 根因（两层，第二层才是真问题）

1. **`fs.watch({recursive:true})` 在 Linux 是用户态实现**（`node:internal/fs/recursive_watch`
   自己 `readdirSync` 遍历整棵树）。我们的事件级过滤 `shouldWatchRelPath`
   **只能拦事件，拦不住 Node 自己往下走**。于是它照样走进 `.zvec-grep/`，而那里正是
   **我们自己**在索引时不断重建的 RocksDB 分片段目录（`index.zvec/<n>/scalar.index.1.rocksdb`）。
   父目录 readdir 与子目录 readdir 之间该目录被换掉 → **ENOENT**。
   → `src/core/watch.js:9-20` 那段注释写的「过滤放在事件入口」**在 Linux 上是不充分的**：
   它解决了「不该响应」，但没解决「不该下去看」。
2. **`watchTree` 没给 FSWatcher 挂 `'error'` 监听**（`src/core/watch.js:106-117` 只有 try/catch
   包同步的 `w(...)` 调用，catch 不到**异步** error 事件）。于是那个 ENOENT 成了
   `Unhandled 'error' event` → **整个 watch 进程直接崩** → P14 等到 120s 超时。

**影响面（比测试严重）**：这不是测试专属。**Linux 上真实用户跑 `nx-kn watch` 或 `nx-kn serve`
（serve 默认起守护）时，索引一churn 就可能把守护进程打崩** —— 而「索引 churn」恰恰是守护自己
触发索引造成的，属于自毁回环。macOS 的 recursive 是原生 FSEvents、不走这条 scandir 路径，
所以**在 macOS 上试不出来**（这也是为什么此前没暴露）。

### 修法（用户选 A：自己递归 + 每目录 watcher；并选「修完发 0.2.1」）

**代码改动**（`src/core/watch.js`）：
- 新增 `shouldSkipDirName(name)`（隐藏目录 + `WATCH_IGNORED_DIRS`，与 `shouldWatchRelPath` 共用名单）
- `watchTree` **不再用 `recursive: true`**：新增 `scan()` 自己从根 `readdir` 枚举目录，
  `shouldSkipDirName` 的目录整棵不下钻 → **逐个目录挂非递归 watcher**
  （`.zvec-grep/` 连 readdir 都不发生 → 回环与 ENOENT 路径同时消失，三平台一致）
- **每个 watcher 都挂 `'error'`**（原来的致命缺口）：只 `report()` 不抛，
  摘掉出错的 watcher + `scheduleRescan()` 稍后重挂（自愈）；`errorDirs` 去重防刷屏
- 目录增删：只有 `eventType === 'rename'` 触发**节流**重扫（`RESCAN_DELAY_MS=200`，可注入）
  —— 一次批量操作只重扫一次，且避开「目录还没建好就扫」的中间态
- 每个 watcher 报的是「相对自己那个目录」的名字 → `relative(rootAbs, join(absDir, name))`
  拼成相对 vault 根的路径再过滤
- 只下钻 `isDirectory()` 的条目（**符号链接不下钻**，避免成环/跑出 vault）
- 返回 `{ close, dirs(), rescan(), error }`；`error` 只在启动阶段失败时有值（契约未变）
- `readdirImpl` 也做成可注入 → 单测用假文件系统，不碰真实磁盘

**`src/modules/kb/watch.js`**：新增 `onWatchError(t, err)` —— 记 `t.error` + `errors++` +
报一条事件（文案「已自动重挂，若持续出现请检查该目录权限」），**不停止守护**；
`onChange` 里 `t.error = null`（能收到变化就说明 watcher 活了，清掉自愈前的旧标记）。
