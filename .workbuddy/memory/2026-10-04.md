## 远程模型 key 入口盘点（应答用户提问）

- 确认 key 的唯一落点是 zg 全局配置 `~/.zvec-grep/config.json`（**当前不存在**，即从未配过
  key）；本机 `~/.zvec-grep/` 下只有 `models/`（本地 qwen3-embedding-0.6b 的 gguf）。
- **nx-kn 目前没有任何 key 入口**：kb 域只有 `use / index / query / status` 四条 action，
  面板也无输入框。要用远程 qwen 只能在终端跑 zg 三步
  （`config provider set` → `config model set --default` → `auth grant`）。
- 实测补两条 0.2.2 接口事实（已同步进 `zg-knowledge-base` 技能）：
  - `zg config` **只写不读**——无 `provider list` / `model get`，报
    `Error: zg config requires provider set or model set`。探测 key 只能看 config.json
    存在性；读当前模型看 `zg status` 的 `Embedding` 行。
  - `zg auth status` 可用于探测授权；当前输出 `Remote Embedding is not authorized`。
- 顺带发现：nx-rp `src/modules/doc/zg.js` 的 `currentModel()` 调 `zg config model get`，
  在 0.2.2 会**永远失败并回退默认值**（它写了 fallback 所以不崩，但拿不到真值）——
  nx-rp 侧待修，nx-kn 不要照抄这个探测方式。
- 待办（待用户定）：是否给 nx-kn 补 key 入口（`nx-kn auth --key` + 面板输入框，照 nx-rp
  三步，key 只落 zg 的 config.json、不入 nx-kn store）。
