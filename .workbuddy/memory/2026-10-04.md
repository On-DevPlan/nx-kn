## 修复「更换目录实际没有更换」（用户报告）

**根因**：`useToast()` 返回的就是 toast 函数本身，但 kb 视图写成 `const { toast } = useToast()`
→ `toast` 恒为 `undefined` → 成功路径上 `toast(...)` 抛 TypeError，**`await refresh()` 永不执行**
→ store.json 其实写成功了，界面却不刷新，用户看到的就是「更换目录没生效」。**静默失效，不报错不白屏。**

**证据链（CDP 实测，非推断）**：
- patch `window.fetch` 抓包：`POST /api/kb/use` 确实发出、后端 200/404 正常，但 `.toast` 恒为空
- React fiber 检测：input 的 `fiber.ref.current === input` 为 true → **ref 正常**，排除「ref 没挂上」
- 对照组：错误路径（不存在的目录）修复前也无提示，修复后弹「知识库目录不存在: …」

**改动（3 处）**：
1. `src/modules/kb/view.jsx` → `const toast = useToast()`
2. `src/modules/settings/view.jsx` → 同上（**模板自带缺陷**）
3. `src/web/frontend/components/ui.jsx` → `useToast()` 加自引用防呆 `toast.toast = toast`，
   让 `const { toast } = ...` 这种写法不再静默失效

**顺带修（也是「像没生效」的成因）**：
- `pickVault` / `reindex` 改为**乐观更新**：POST 响应已含新目录全部信息，直接落 UI。
  此前要等 `refresh()` 跑完（probe + status 两个 zg 子进程，实测 ~4s）界面才变
- busy 期间按钮文案「保存中…」（此前只 disabled、无任何反馈）

**实测数据**：保存后 **400ms 内**目录行已更新、按钮已恢复可用（修复前 3000ms 仍是旧值、4s 才恢复）。

**模板级缺陷（未动 nx-nx）**：`nx-nx/templates/server-cli-web/files/src/modules/settings/view.jsx:17`
同样是 `const { toast } = useToast()` —— 该模板生成的所有项目 settings 页都带此病，待第 4 步处理。

**另注**：store.json 的 `kb.model` 现在是 `local/potion-code-16m-v2`（不是我设的，我没用它跑过
索引；`use` 不写 model，只有 `index` 会写）。vault 已确认恢复为 `D:\Obsidian Vault`
（226 篇，**尚无索引**）。

**待办**：换库后「模型」行显示的是 store 里上一个库的 model（`status()` 的
`idx?.embedding?.model || storedModel()` 在无索引时回落 store），语义上该显示「（未记录）」。

## 计划 ↔ 实现对账（用户要求「检查和plan差别」）

**新实测的三条 zg 事实（已同步进对账文档）：**
- **`zg index` 默认即增量**：3 篇库加 1 篇后跑无 `--rebuild` 的 index → `3 scanned, 1 added,
  2 unchanged`，实体 2→3。已建向量保留。这解答了 plan §4 的未决疑问；`--rebuild` 只在换模型时需要。
- **`zg query --trace` 暴露 `score=`，是标准 RRF**（`2/61 = 0.0328`，`1/61 ≈ 0.0161`）。
  这是**多库合并排序的唯一可用依据**（排名派生，跨库相对可比）。
- **给 query 加 `--trace` 会静默污染路径**：`HIT_RE` 的 `(.+)` 贪婪吃掉 `score=0.0328 `，
  `hit.path` 变成 `"score=0.0328 a.md"` —— 必须同步改正则（可选 score 组）+ 加单测。

**用户决策**：多目录知识库（不是单库增量）。改动面见对账文档 §5。

**关键校正**：vault 真实笔记是 **226 篇**（不是 551）。551 是我用
`Get-ChildItem -Recurse -Filter *.md`（不带 -Force，不排除隐藏）数出来的，其中
**`.obsidian/` 占 325 篇（59%）** —— 排除规则不是可选项。`nx-kn inspect()` 的 226 是对的。

**其他核对结果**：`D:\Obsidian Vault` 从未建过索引（无 `.zvec-grep`）；`~/.zvec-grep/config.json`
不存在（从未配 key / 默认模型）；vault 是 **git 仓库**（`.git` 存在 → `.zvec-grep/` 会进 git 工作区，
plan §5.4 的风险成立）；命令表 15 条、单测 19/19 全绿。

**遗留缺陷**（挡在多库之前）：`store.kb.model` 全局单值（多库需每库一个）且现值
`local/potion-code-16m-v2` 与任何现存索引都不符；`status()` 无索引时回落 store 显示假模型；
`hasIndex()` 不校验模型一致性；**面板只有「重建索引」按钮**（增量能力 CLI 有、面板没暴露 ——

## 多库改造 + 增量入口（用户：「支持增加，而不是替换原本的索引」→ 选「多目录知识库」）
